## Goal

Expose the mobile incident-list endpoint under `/mobile/v1` with the response shape and behavior shown in issue #41, without changing the existing internal API.

## Steps

1. In the owned file `incidentdesk/api/mobile_incidents.py`, add the mobile list route and its response model, using the existing incident data and following issue #41's response example.
2. In the shared file `incidentdesk/app.py`, add `from incidentdesk.api import mobile_incidents` and `app.include_router(mobile_incidents.router)`.
3. In the owned file `tests/api/test_mobile_incidents.py`, add focused endpoint tests.
4. In the shared file `CHANGELOG.md`, add `- Mobile clients can page through open incidents at \`/mobile/v1/incidents\`.` under `## Unreleased`.

## Tests

- Verify the list endpoint's status code, response fields, and values match issue #41's response example.
- Verify that only open incidents are returned, newest first, 20 per page, and that `next_page` is null on the last page.
- Run `scripts/test.sh tests/api/test_mobile_incidents.py`; it runs the selected tests in UTC and Asia/Singapore.

## Risks

- Owned files: `incidentdesk/api/mobile_incidents.py` and `tests/api/test_mobile_incidents.py`.
- Shared additions: the import and router-registration lines in `incidentdesk/app.py` above, plus the single Unreleased bullet in `CHANGELOG.md` above. Sub-issues #42 and #43 also add their own import/registration lines and one changelog bullet to those files; retain all three additions when integrating the branches.
- This sub-issue does not depend on #42 or #43. It shares no request or response models with them.

## Out of scope

- Incident detail and timeline behavior from #42.
- Alert subscriptions from #43.
- Changes to the existing internal incident API.
