## Goal

Expose the mobile alert-subscription endpoint under `/mobile/v1` with the response shape and behavior shown in issue #43.

## Steps

1. Add the mobile alert-subscription route in `incidentdesk/api/mobile_alerts.py`, following issue #43's request and response examples.
2. Add any subscription request/response models in `incidentdesk/schemas.py`.
3. Add a persistence model for subscriptions in `incidentdesk/models.py` if required by issue #43's contract.
4. Register the router in `incidentdesk/app.py`.
5. Add focused endpoint tests in `tests/api/test_mobile_alerts.py`.
6. Add a plain-language entry under `## Unreleased` in `CHANGELOG.md`.

## Tests

- Verify the subscription endpoint's status code, response fields, and values match issue #43's response example.
- Verify persistence and invalid-input or duplicate-subscription behavior where specified by issue #43.
- Run `scripts/test.sh tests/api/test_mobile_alerts.py`; it runs the selected tests in UTC and Asia/Singapore.

## Risks

- `incidentdesk/app.py`, `incidentdesk/schemas.py`, and `CHANGELOG.md` are also changed by sub-issues #41 and #42; coordinate these shared-file edits when integrating the parallel branches.
- This sub-issue does not depend on #41 or #42. If its contract requires persistent subscriptions, its model and endpoint must be implemented together; there is no separate migration framework in the current repository, so align any schema rollout with the repository's existing database setup.

## Out of scope

- Incident list behavior from #41.
- Incident detail and timeline behavior from #42.
- Changes to existing internal incident or notification behavior.
