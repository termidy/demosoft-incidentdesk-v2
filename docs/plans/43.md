## Goal

Expose the mobile alert-subscription endpoint under `/mobile/v1` with the response shape and behavior shown in issue #43.

## Steps

1. In the owned file `incidentdesk/api/mobile_alerts.py`, add the subscription routes and their request/response models, following issue #43's examples.
2. In the owned file `incidentdesk/mobile_subscriptions.py`, add the subscription persistence model so this sub-issue does not edit the shared `incidentdesk/models.py`.
3. In the shared file `incidentdesk/app.py`, add `from incidentdesk.api import mobile_alerts` and `app.include_router(mobile_alerts.router)`.
4. In the owned file `tests/api/test_mobile_alerts.py`, add focused endpoint tests.
5. In the shared file `CHANGELOG.md`, add `- On-call engineers can manage mobile alert subscriptions by service and minimum priority.` under `## Unreleased`.

## Tests

- Verify `POST /mobile/v1/subscriptions` stores a subscription and returns it with an ID and status 201; verify `GET /mobile/v1/subscriptions?engineer=a.reyes` lists that engineer's subscriptions.
- Verify an unknown service returns 422.
- Run `scripts/test.sh tests/api/test_mobile_alerts.py`; it runs the selected tests in UTC and Asia/Singapore.

## Risks

- Owned files: `incidentdesk/api/mobile_alerts.py`, `incidentdesk/mobile_subscriptions.py`, and `tests/api/test_mobile_alerts.py`.
- Shared additions: the import and router-registration lines in `incidentdesk/app.py` above, plus the single Unreleased bullet in `CHANGELOG.md` above. Sub-issues #41 and #42 also add their own import/registration lines and one changelog bullet to those files; retain all three additions when integrating the branches.
- This sub-issue does not depend on #41 or #42. It shares no request or response models with them; the owned persistence model is implemented alongside this endpoint.

## Out of scope

- Incident list behavior from #41.
- Incident detail and timeline behavior from #42.
- Changes to existing internal incident or notification behavior.
