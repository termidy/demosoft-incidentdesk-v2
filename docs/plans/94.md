## Goal

Lock the mobile API's list, detail, and alert-subscription request and response contracts in focused API tests.

## Steps

1. Add `tests/api/test_mobile_contract.py` with contract tests for the list response and pagination, the incident detail and not-found response, and subscription creation, listing, and unknown-service response.

## Tests

- The list response has the documented fields and values, and pagination has the documented `next_page` behavior: `test_mobile_list_contract` in `tests/api/test_mobile_contract.py`.
- Incident detail has the documented fields and timeline order, and an unknown incident returns the documented not-found response: `test_mobile_incident_detail_contract` and `test_mobile_incident_not_found_contract` in `tests/api/test_mobile_contract.py`.
- Subscription creation and listing use the documented request and response fields, and an unknown service returns the documented validation status: `test_mobile_subscription_contract` and `test_mobile_unknown_service_contract` in `tests/api/test_mobile_contract.py`.
- Run `scripts/test.sh tests/api/test_mobile_contract.py` to run the contract tests in UTC and Asia/Singapore.

## Risks

- The new tests must assert the existing `/mobile/v1` public contract rather than encode implementation details, so future internal changes do not break compatible clients.
- The mobile endpoints already exist; this sub-issue adds tests only and must not alter their behavior.

## Out of scope

- Changes to mobile API implementation, documentation, or internal API behavior.
