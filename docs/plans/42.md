## Goal

Expose mobile incident detail and timeline endpoint(s) under `/mobile/v1` with the response shape and behavior shown in issue #42, without changing the existing internal API.

## Steps

1. Add the mobile detail and timeline route(s) in `incidentdesk/api/mobile_incident_detail.py`, using the existing incident and timeline data and following issue #42's response examples.
2. Add any mobile detail or timeline response models in `incidentdesk/schemas.py`.
3. Register the router in `incidentdesk/app.py`.
4. Add focused endpoint tests in `tests/api/test_mobile_incident_detail.py`.
5. Add a plain-language entry under `## Unreleased` in `CHANGELOG.md`.

## Tests

- Verify detail and timeline status codes, response fields, and values match issue #42's response examples.
- Verify behavior for an unknown incident and any timeline filters or ordering specified in issue #42.
- Run `scripts/test.sh tests/api/test_mobile_incident_detail.py`; it runs the selected tests in UTC and Asia/Singapore.

## Risks

- `incidentdesk/app.py`, `incidentdesk/schemas.py`, and `CHANGELOG.md` are also changed by sub-issues #41 and #43; coordinate these shared-file edits when integrating the parallel branches.
- This sub-issue does not depend on #41 or #43. It can reuse existing incident lookup and timeline data without requiring the mobile list endpoint.

## Out of scope

- Incident list behavior from #41.
- Alert subscriptions from #43.
- Changes to the existing internal incident and timeline API.
