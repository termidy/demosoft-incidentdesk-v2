## Goal
Teams can download a completed postmortem as Markdown, while drafts without a root cause cannot be exported.

## Steps
1. Add `GET /postmortems/{key}/export.md` in `incidentdesk/api/postmortems.py`, returning the title, incident key, Summary, Impact, Root cause, and Actions as a Markdown checklist; reject a postmortem without a root cause.
2. Extend `tests/api/test_postmortems.py` to cover the Markdown response for a published postmortem, rejection of a draft without a root cause, and a missing key.
3. Add a plain-language entry under `## Unreleased` in `CHANGELOG.md`.

## Tests
- For a published postmortem such as PM-101, assert the Markdown media type and that the title, incident key, all required section headings and contents, and checklist actions appear in the response.
- For a draft without a root cause, assert the export request is rejected and no Markdown is returned.
- For an unknown key, assert the export endpoint returns 404.
- Run `tests/api/test_postmortems.py` with `DATABASE_URL` configured; its database-marked tests are skipped otherwise.

## Risks
The export could omit or mislabel fields, or format actions as ordinary text; assertions against every section and checklist marker will catch that. A draft might accidentally be exported with an empty root-cause section; the draft rejection test will catch it.

## Out of scope
Changing postmortem creation, editing, publishing, or JSON endpoints; supporting Markdown import or editing.
