## Goal

Give mobile-app developers a concise reference for the `/mobile/v1` endpoints, their requests, responses, pagination, and errors.

## Steps

1. Add `docs/mobile-api.md` documenting the incident list and detail endpoints and alert-subscription create and list endpoints, including examples matching the existing API contract.

## Tests

- The incident-list example and pagination details match the API response and behavior: `test_mobile_list_matches_response_example` and `test_mobile_list_filters_sorts_and_paginates_unresolved_incidents` in `tests/api/test_mobile_incidents.py`.
- The incident-detail example, oldest-first timeline, and not-found response match the API: `test_mobile_incident_detail_includes_timeline_oldest_first` and `test_mobile_incident_detail_returns_not_found` in `tests/api/test_mobile_incident_detail.py`.
- The subscription create/list example and unknown-service response match the API: `test_create_and_list_subscriptions` and `test_unknown_service_is_refused` in `tests/api/test_mobile_alerts.py`.

## Risks

- Stale request or response examples could mislead mobile clients; verify each example against its named endpoint test.
- Keep the reference limited to the public mobile API and do not imply that internal API behavior is part of this contract.

## Out of scope

- API implementation or contract-test changes.
- Changes to the internal API or general IncidentDesk documentation.
