## Goal

Ensure `POST /incidents` accepts only titles that contain 1–200 characters after surrounding whitespace is removed, and stores accepted titles trimmed.

## Steps

1. Update `incidentdesk/schemas.py` to validate the trimmed title length from 1 through 200 characters.
2. Keep `incidentdesk/incidents.py` storing the title without surrounding whitespace, and add or adjust focused schema and API tests in `tests/unit/test_schemas.py` and `tests/api/test_incidents.py` to cover whitespace-only titles, 200- and 201-character titles, trimmed storage, and no incident creation on rejection.
3. Add a plain-language entry under `## Unreleased` in `CHANGELOG.md`.

## Tests

- `tests/unit/test_schemas.py`: check that whitespace-only and over-200-character titles fail validation, while a 200-character title succeeds.
- `tests/api/test_incidents.py`: check rejected requests return 422 and create no incident; verify a padded valid title is returned trimmed.
- Run the focused tests through `scripts/test.sh`, then run `scripts/test.sh` for the whole suite in UTC and Asia/Singapore.

## Risks

- Validation before stripping could accept whitespace-only input or miscount padded titles; test lengths after trimming.
- Rejecting an invalid title after incident creation could leave partial data; check the incident count after rejected API requests.

## Out of scope

- Existing incidents, `/mobile/v1`, alert intake, and any title-handling paths outside `POST /incidents`.

For context, this plan also reviewed postmortem PM-117 (INC-4906, “Billing service: database connections exhausted”).
